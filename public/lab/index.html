🐢 Building in public

Turtle Lab

The live build log for TurtleBlock AI's conversational constructivist agent and persistent WorldSpec architecture.

Current milestone

Discord /turtle is live in the STEAMHAMLET server. The first end-to-end flight successfully moved a learner idea through Discord, the TurtleBlock Cloudflare Worker, WorldSpec interpretation, and back into Discord.

What we learned immediately

The plumbing worked. The interpretation was too shallow. A rich learner description of an abandoned village, remembered order, disarray, hope, light, and rebirth was compressed into a small set of known parser cells. That field test changed the architecture.

lossless learner language → dialogue → incremental WorldSpec revisions → learner-authorized construction → inhabit → notice → reflect → revise

The new direction

  • Turtle is a conversational collaborator governed by the Turtle Charter, not a one-shot parser.
  • Every new Turtle Lab begins a persistent WorldSpec instance immediately.
  • The learner's original language is retained even when Turtle has no existing lexicon entry for it.
  • WorldSpec is edited incrementally through dialogue rather than regenerated from scratch every turn.
  • Turtle should ask one or two generative questions at a time and keep the learner in control of when conversation becomes construction.
  • WorldSpec revisions retain provenance: learner statements, Turtle interpretations, world observations, and manual edits remain distinguishable.

Discord Turtle Lab

The preferred field-test experience is for /turtle idea:... to create a dedicated Turtle Lab thread. Turtle then continues the conversation there while the same persistent WorldSpec evolves underneath it.

Turtle may eventually be callable from any permitted channel. Dedicated threads are preferred over creating a new top-level server channel for every project because they preserve context without filling the server with permanent channels.

Persistent WorldSpecs

Active sessions will use persistent storage for session state, turns, WorldSpec instances, and revisions. Portable WorldSpecs remain exportable as YAML/JSON artifacts. Operational project storage remains separate from research datasets and public examples.

LLM conversation + RAG + security

Turtle's conversational layer is being wired to an LLM while WorldSpec remains persistent source-of-truth state. Retrieval will supply the current WorldSpec, learner definitions, unresolved concepts, active constraints, recent dialogue, relevant revisions, and intentionally attached project context.

learner turn → retrieve bounded context → Turtle Charter + action policy → LLM dialogue → structured WorldSpec delta → validate → persist revision → conversational reply

Retrieved documents, Discord history, learner messages, Minecraft text, and prior model output are treated as untrusted data rather than executable instructions. Construction and other external actions require deterministic validation outside the language model.

Next implementation target

Complete LLM-backed Discord opening dialogue, then create the Turtle Lab session manager: Discord thread creation, persistent session state, first WorldSpec revision, ongoing turn capture, and incremental WorldSpec deltas.

Build-in-public rule

Meaningful architecture, pedagogy, integration, research-data, and WorldSpec milestones should be reflected on the public TurtleBlock AI site as part of the same work cycle. Failures and reversals count as milestones too.
