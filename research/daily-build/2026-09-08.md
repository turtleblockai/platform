## Sanders ontology mapping

### Personal Inquiry
The learner's original intention must remain primary data. External models or retrieved research can inform but should not replace it.

### Compelling Problem or Question
Ambiguity and disagreement are productive when preserved long enough to generate new questions instead of being silently normalized away.

### Technology as Tool to Think With
The agent is valuable when its interpretation becomes material the learner can inspect, challenge, and revise.

### Formative Demonstration of Learning
A correction is evidence of developing thought. The system should record the change rather than only display the latest state.

### Reflection as Learning
The before/after relationship between learner intent, Turtle interpretation, and learner correction creates a concrete object for reflection.

### Social and Cultural Critique
A visible trace helps reveal when a machine imposes assumptions, categories, or values the learner did not supply.

### Sharing and Collaborating
The same trace can later help collaborators understand how a shared WorldSpec changed and whose intervention changed it.

### Co-active Emergence
The strongest fit is the visible exchange itself: human idea → machine interpretation → human steering → revised shared artifact. Neither side should be rewritten out of the history of the result.

## Deliberation

### Candidate A — Generalized persistent personal memory

**Why attractive:** NVIDIA demonstrates clear benefits for structured memory.

**Why not now:** TurtleBlock already has persistent project/session architecture, and generalized personal memory introduces privacy, identity, deletion, and preference-governance questions. That belongs closer to the v0.3 milestone, not a v0.1 micro-change.

**Decision:** Defer.

### Candidate B — Cross-school Minecraft dedicated-server collaboration

**Why attractive:** Minecraft Education now makes this materially more feasible.

**Why not now:** This is a substantial collaboration/infrastructure feature and maps better to v0.4. Pulling it forward would violate the deliberately slow version path.

**Decision:** Track as roadmap evidence, do not build today.

### Candidate C — More autonomous agentic research/build behavior

**Why attractive:** OpenAI shows research acceleration with agents and concurrent agent workflows.

**Why not now:** TurtleBlock's current research problem is not agent throughput. More autonomy could hide interpretation and weaken learner agency if added prematurely.

**Decision:** Do not build as a learner-facing feature.

### Candidate D — Co-Active Trace

**Why attractive:** It is small, local to the current Try It flow, supported independently by OpenAI's human-supervised evaluation pattern, NVIDIA's correction/audit design, MIT's visible-feedback/easy-correction lineage, and Sanders' own ontology.

**Decision:** Build next.

## Proposed micro-build — Co-Active Trace

After Turtle produces an initial WorldSpec interpretation, expose a small steering checkpoint:

- **Keep** — the interpretation matches the learner's intention closely enough to continue.
- **Change** — the learner supplies a correction or replacement interpretation.
- **Question** — the learner wants Turtle to explain or interrogate an interpretation before accepting it.

Preserve these as distinguishable provenance states:

```text
learner_intent
  ↓
turtle_interpretation_v1
  ↓
ontology_hits
  ↓
human_steering { keep | change | question }
  ↓
turtle_interpretation_v2 / accepted_state
  ↓
worldspec_revision
```

### Required properties

1. Original learner text is never overwritten.
2. Turtle's first interpretation remains inspectable.
3. Human correction is attributed to the human, not retroactively presented as Turtle's original understanding.
4. The resulting WorldSpec revision records the transition.
5. Ontology links are explanatory metadata, not authority over learner meaning.
6. The learner may reject the ontology interpretation itself.

## Tiny test

**Prompt**

> Build a village near a dangerous forest where people have to decide whether to cut trees or protect them.

Allow Turtle to produce an initial interpretation. Then choose **Change** and enter:

> The forest is not an enemy; it should have its own needs and agency.

### Pass criteria

- The new WorldSpec reflects the correction.
- The original prompt remains available.
- Turtle's earlier interpretation remains available.
- The learner correction is recorded as learner-authored steering.
- No UI or data representation implies Turtle knew the correction before the learner supplied it.
- The trace is readable enough that another person can understand why the WorldSpec changed.

## Open research question — can Turtle talk to Turtle?

Yes, but it should be treated as **synthetic self-play**, not as learner activity.

A bounded future experiment could separate two roles:

```text
Builder Turtle
  ↓ proposal / WorldSpec delta
Reflector Turtle
  ↓ Charter + ontology + regression critique
Builder Turtle
  ↓ revision
synthetic trace
  ↓
external test + human gate
```

Machine-to-machine dialogue could be useful for regression testing, adversarial interpretation checks, WorldSpec edge cases, ontology retrieval testing, and candidate repository changes. The key research boundary is provenance: self-play records must be explicitly labeled synthetic, kept separate from human learner evidence, and prevented from promoting their own work directly into production merely because the two agents agree.
